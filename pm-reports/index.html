How your project file works项目文件使用说明

Three steps: perfect your template, start a project, then manage it with Muse.三步：定好模板，开新项目，和 Muse 一起管理。

Step 1第一步Make the template yours定好你的模板

template.csv is the master copy of how you build. Every new project starts as a copy of it. Get it right once, and every future project starts right.template.csv 是你的母版，记录你怎么做项目。每个新项目都是从它复制出来的。一次定好，以后的每个项目起点都是对的。

➕

Add a task加任务

Add a row with a new id (T108, T109…). New projects pick it up automatically.加一行，用新的编号（T108、T109…）。新项目会自动包含它。

⏱️

Fix a duration改工期

Learned framing takes 40 days, not 30? Change typical_duration_days.发现 framing 要 40 天不是 30 天？改 typical_duration_days。

🔗

Rewire the order改顺序

Change depends_on to say what waits for what.改 depends_on，说明谁等谁。

Changing the template never touches projects already underway — only new ones. After editing, ask Muse to validate it.改模板不会影响已经在做的项目——只影响新项目。改完让 Muse 检查一遍。

Step 2第二步Start a new project开新项目

You never run commands yourself — just describe what you want.你不用自己敲命令——只管说要什么。

1
Tell Muse the name, address, and start date.
Example: "Create a new project: Oak Ave Residence, 567 Oak Ave, Sunnyvale, starting January 5."告诉 Muse 项目名、地址和开工日期。
比如："新建项目：Oak Ave Residence，地址 567 Oak Ave, Sunnyvale，1 月 5 日开工。"
2
Muse builds the file from your template — all 61 tasks, dates auto-scheduled. Takes seconds.Muse 用你的模板生成文件——61 个任务，日期自动排好。几秒钟。
3
Adjust to reality. Move dates, assign owners. The template was the starting point — this project file is now yours to run.按实际情况调整。改日期、指定负责人。模板只是起点——这个项目文件现在由你来管。

Step 3第三步Run the project with Muse和 Muse 一起管项目

Each project lives in its own file. Here's how to read and update it.每个项目都有自己的文件。下面教你怎么看、怎么改。

📄

One file per project一个项目，一个文件

Maple Street has its own file. Oak Ave has its own file. You always know where to look.Maple Street 有自己的文件，Oak Ave 也有自己的文件。永远知道去哪里找。

📝

Each row is a task每一行是一个任务

61 rows = 61 tasks, from the soil report to the final key handover.61 行 = 61 个任务，从土壤报告到最后交钥匙。

🤖

Muse double-checksMuse 帮你检查

You edit freely. Muse validates every change and warns about broken order or dates.你放心改。Muse 会检查每一次修改，顺序或日期错了会提醒你。

Dates日期列 — planned = the plan, actual = what really happened. Always write like 2026-10-10.planned 是计划，actual 是实际发生的情况。永远写成 2026-10-10 这种格式。

The columns, by color各列说明（按颜色）

🟢 Edit freely随便改

  • status — not_started → in_progress → complete. Use blocked when waiting on someone.not_started → in_progress → complete。等人的时候用 blocked。
  • planned_start / planned_end — The plan. Move them when reality shifts.计划日期。实际情况变了就改。
  • actual_start / actual_end — What really happened. Fill in when a task starts / finishes.实际发生的日期。任务开始 / 结束时填写。
  • owner — Who's doing it: a crew name, a sub, or your own name.谁在做：施工队、分包商，或你自己的名字。
  • notes — Anything worth remembering: "waiting on the city", "passed with no corrections".值得记的事："等市政府"、"一次通过"。

🟡 Careful小心改

  • depends_on — Which tasks must finish first. Ask Muse if you're unsure.哪些任务必须先完成。不确定就问 Muse。
  • typical_duration_days, long_lead, lead_time_days, inspection_gate, milestone — These describe how the plan itself works. Change only when the plan changes.这些描述计划本身的规则。只有计划变了才改。

🔴 Don't touch不要碰

  • task_id, stage_id — The glue that links rows together. Changing these breaks the links.连接各行的胶水。改了会导致关联断裂。

The round trip: Numbers → Muse修改流程：Numbers → Muse

1
Open the project's CSV in Numbers.在 Numbers 里打开项目的 CSV 文件。
2
Edit — green columns freely, yellow carefully.修改——绿色列随便改，黄色列小心改。
3
File → Export To → CSV.文件 → 导出到 → CSV。
4
Send the file to Muse. It validates, fixes formatting, and saves.把文件发给 Muse。它会检查格式、修正，然后保存。

What if I make a mistake?改错了怎么办？

Almost impossible to break anything. Muse checks every file before saving and tells you exactly which row has a problem. Every version is kept, so nothing is ever truly lost. When in doubt, just ask Muse.基本不可能搞坏。Muse 保存前会检查每个文件，哪一行有问题会明确告诉你。而且每个版本都有保留——不会真正丢失。不确定就问 Muse。
